# Native Rust architecture

The application ships as one native executable with a statically linked CRT. The tray/core process uses `windows-sys`; Settings launches the same executable with `--settings-ui` to host genuine WinUI 3 controls through Microsoft's `windows-reactor` 0.100.0. Closing Settings exits that child and releases the XAML runtime. No .NET or browser engine is used. The framework-dependent UI requires Microsoft.WindowsAppRuntime.2 >= 2.4.0.0. Reactor 0.100 uses Windows 11's dynamic package dependency APIs, so this build targets Windows 11 (22000+); retained Windows 10 COM profiles do not imply Windows 10 support. Reactor is an early Microsoft API and is pinned to avoid unreviewed breaking changes.

`src/settings.rs` preserves all 61 v2 settings, custom `hotkeys.*` entries, quoted strings, Unicode escapes, comment lines, and `--key value` / valueless boolean flags. Files in the existing roaming configuration directory load in lexical order, with the main file last. CLI values override files and are never saved. Writes use a temporary file and `MoveFileExW` with replace/write-through. Advanced settings expose the complete file configuration.

`src/platform/desktop.rs` owns apartment-bound COM pointers and releases them with RAII. `profiles.rs` preserves the nine original VirtualDesktopAPI profiles. Interfaces are selected by successful `QueryService` for a known IID, with an OS build guard for the 21H2/22H2 profiles that share an IID but differ in layout. An unsupported interface is reported rather than guessed. Previous-desktop history uses GUIDs, including after reorder/removal.

`src/platform/events.rs` blocks on `RegNotifyChangeKeyValue` for Explorer's VirtualDesktops subtree and the current session's desktop key where present. The UI refreshes cached desktop data only on change or user action. A WinEvent foreground hook and the published GetWindowDesktopId API replace focus polling; `WM_SETTINGCHANGE`, `WM_THEMECHANGED`, and `WM_DISPLAYCHANGE` handle theme/display changes. Explorer's `TaskbarCreated` broadcast reconnects COM, restarts the watcher and restores tray icons. Reconnection uses at most six bounded one-shot retry timers; there is no steady-state polling. Shutdown signals and joins the watcher before destroying its target window.

`src/hotkeys.rs` is the WindowsHotKeyAPI replacement: parsed and validated bindings, RegisterHotKey/WM_HOTKEY, conflict reporting and automatic unregister. `platform/input.rs` is the WindowsInputAPI replacement: SendInput chords for Task View and fallback left/right navigation, preserving held modifiers and cleaning up partial injections.

`src/ui/settings.rs` contains reusable WinUI setting cards using NavigationView, ToggleSwitch, ComboBox, NumberBox, Expander and InfoBar. The layout responds to window width and uses theme brushes and Mica. Shortcuts are recorded with a temporary keyboard hook, scoped to the foreground Settings process. Native overlays provide the actual preview. Less common settings and custom hotkeys remain in Advanced.

`settings_process.rs` owns the Settings child and exchanges validated file settings with the parent using synchronous WM_COPYDATA. The parent preserves CLI overrides, registers shortcuts, atomically saves, and acknowledges success before the UI commits its state. Failed changes restore the previous registrations and settings. No IPC listener or polling timer runs while Settings is closed.

Tray glyphs render into a supersampled grayscale mask and become premultiplied BGRA icons with true alpha. Visible glyph bounds, rather than font em size, determine the fit, keeping chevrons and digits equally legible. Their pixel size follows the taskbar DPI and colors follow the taskbar theme. Existing icons update in place. Settings shares the icon selection and rasterizer, decodes the same pixels as alpha-preserving BMP V5 images, and observes desktop and theme changes without polling. The preview reflects enabled icons, current desktop, custom symbols/fonts/colors and boundary opacity; Explorer controls final order and spacing. Overlay geometry uses device-independent pixels, scaled separately for each monitor; fonts use points, and placement is constrained to the work area.

`scripts/build-msix.ps1` builds architecture-specific Cargo release binaries, validates an MSIX with MakeAppx, checks the native PE payload, and emits portable ZIP, MSIX, Store upload archive and SHA-256 files in `dist/`. Signing is explicit. Store identity files are preserved. Historical published Scoop downloads remain in `installers/scoop`.

The undocumented Windows desktop interfaces still require compatibility testing on each supported Windows build. A successful build or current-machine smoke test does not establish compatibility across every Windows/Insider release. See [validation](validation.md).
